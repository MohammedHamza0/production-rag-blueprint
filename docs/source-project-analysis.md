### 2. مصفوفة تتبع القرارات والأنماط (Traceability Matrix: Source -> Blueprint)

| القدرة الهندسية (Capability) | المصدر المرجعي (Source System) | التصميم المعتمد في المخطط العام (Generalized Blueprint Design) | مسوغات التجريد والتطوير |
| :--- | :--- | :--- | :--- |
| **الكاش الدلالي المتقدم** | `Tadabbur`: `SemanticCache.js` (Migration 002) + `CacheEquivalenceVerifier.js` | **نواة كاش دلالي رباعية الأبعاد في بايثون** تجمع فحص L1 و L2 مع فحص التكافؤ التام للأبعاد الحرجة. | في المشاريع الحساسة، التشابه الدلالي $\ge 0.90$ لا يعني التكافؤ. تم حل المشكلة بمدقق التكافؤ مع قفل الطيران الفردي. |
| **حماية التدافع المتزامن** | `Midade RAG`: `SingleFlightCache.js` | **قفل طيران فردي موزع (`SingleFlightMutex`)** عبر أنابيب Redis الذرية. | منع انهيار الخوادم وتكرار استدعاءات LLM باهظة التكلفة عند هجوم الأسئلة المتزامنة. |
| **البحث الهجين خماسي المسارات** | كلا المشروعين: دالة `search_chunks_hybrid` | **دالة SQL هجينة عامة** تدمج بحث HNSW الكوسيني مع 5 قواميس GIN معجمية عبر RRF $k=60$. | أثبتت التجربة تفوق RRF $k=60$ على كافة محاولات الترتيب العصبي المستقل من حيث السرعة والشمول. |
| **تجريد البنية الهرمية للمستندات** | `Midade RAG`: نموذج `FRBR` (Works > Editions > Documents) | **نموذج معرفي ممتد وعام (Extended Domain Entities)** يدعم الأعمال والطبعات والوثائق والمقاطع. | التجريد يلائم الكتب والمجلات والأوراق البحثية والقوانين دون تسميات خاصة بمشروع محدد. |
| **التجزئة الأبوية-الفرعية** | كلا المشروعين: `StructuralChunker` + `IslamicBookChunker` | **نظام تجزئة مرن (`Pluggable Chunker`)**: مقاطع فرعية ~280t للبحث، ومقاطع أبوية ~1000t للسياق. | إلغاء التبعية على التعبيرات النمطية الخاصة بالكتب الإسلامية، وجعلها قواعد قابلة للتكوين والتوصيل. |
| **التدقيق السريع والتوجيه** | كلا المشروعين: `PolicyGuard.js` | **محرك سياسات قابل للتكوين (`Configurable PolicyGuard`)** للردود الفورية في أقل من `1ms`. | يوفر أكثر من 30% من استهلاك الموارد المهدورة على التحيات والشكر والأسئلة الخارجة عن النطاق. |
| **محاذاة الاستشهادات وتدقيقها** | `Tadabbur`: `CitationSanitizer.js` + `CitationValidator.js` | **محرك تدقيق ومحاذاة قطعي 1:1** يحول الأرقام، يحذف الأشباح، ويقيس الاستلزام المعجمي. | تفويض ترقيم المراجع للـ LLM ينتج أرقاماً وهمية. المعالجة الحتمية الصارمة هي الضمانة الوحيدة. |
| **خزنة المفاتيح المموهة** | كلا المشروعين: `KeyVault.js` | **مزود أسرار متعدد الوسائط (`SecretsProvider`)** يدعم التقسيم التمويهي والمزودات السحابية. | حماية المفاتيح الحساسة من الفحص الساكن ومن تسريبات بيئة التشغيل. |

### 3. الأنماط المصدرية المستبعدة وأسباب استبعادها (Rejected Source Patterns)

1. **الاعتماد على بيئة Node.js / JavaScript في النواة:**
   - *سبب الاستبعاد:* النظام الإنتاجي المستهدف يجب أن يكون مكتوباً بالكامل بلغة **Python 3.12+** لتمكين التكامل الطبيعي مع منظومات الذكاء الاصطناعي، نماذج التضمين المحلية، أطر التقييم، وتجنب ازدواجية اللغات في الفرق التقنية.
2. **استخدام نماذج Gemini 2.5:**
   - *سبب الاستبعاد:* توجيه المستخدم الصريح بأن `gemini-2.5-flash` لم يعد مدعوماً. تم الاستبدال بنماذج **Gemini 3.5 (Flash Lite & Flash)** مع توفير نماذج بديلة.
3. **تضمين نصوص ومسميات برمجية متعلقة بمجال محدد:**
   - *سبب الاستبعاد:* احتوت المشاريع المرجعية على أسماء مثل `TadabburJournalChunker`, `DaiyahMentor`, `QuranicBracket`, `DALEL_VOLUMES_MAP`. تم تجريد هذه المفاهيم إلى واجهات عامة: `AcademicJournalChunker`, `ScripturalBracketPolicy`, `VolumeMetadataResolver`.
4. **تعدد استدعاءات LLM المتسلسلة قبل التوليد:**
   - *سبب الاستبعاد:* استدعاء النموذج لإعادة الصياغة، ثم استدعاؤه لترجمة السؤال، ثم استدعاؤه للترتيب كان يرفع زمن أول توكن إلى أكثر من 6 ثوانٍ. تم استبدالها بمسارات متوازية وخوارزميات ترتيب محلية سريعة.
